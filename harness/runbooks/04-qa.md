# 04. QA 실행

이 문서는 API가 request contract대로 동작하는지 실제 HTTP 요청으로 확인하는 절차입니다.

## QA가 필요한 경우

- 새 API 추가
- 기존 API request/response 변경
- SecurityConfig 권한 변경
- WebAdapter path, query parameter, path parameter, request body 변경
- DB query 결과가 response에 영향을 주는 변경

## 사전 확인

1. `01-intake.md`를 통과한 request contract가 있습니다.
2. `02-fixture-plan.md`에 따라 synthetic fixture가 준비됐습니다.
3. `03-env-up.md`에 따라 앱이 떠 있습니다.
4. `SecurityConfig.java`와 `WebAdapter.java`를 확인할 수 있습니다.

## SecurityConfig 확인

request contract의 method, path, authority와 `SecurityConfig.java`가 일치해야 합니다.

확인 명령어:

```powershell
Select-String -Path jobis-infrastructure\src\main\java\team\retum\jobis\global\security\SecurityConfig.java -Pattern "interviews|requestMatchers|hasAuthority|hasAnyAuthority"
```

확인 기준:

- public API가 아니면 Authorization header가 필요합니다.
- contract authority가 `TEACHER`, `STUDENT`이면 SecurityConfig도 같은 authority를 허용해야 합니다.
- contract와 SecurityConfig가 다르면 QA 실패입니다.

## WebAdapter 확인

method, path, query parameter, path parameter, request body가 contract와 같아야 합니다.

확인 명령어:

```powershell
Get-ChildItem jobis-infrastructure\src\main\java\team\retum\jobis\domain -Recurse -Filter *WebAdapter.java | Select-String -Pattern "GetMapping|PostMapping|PatchMapping|PutMapping|DeleteMapping|RequestParam|PathVariable|RequestBody"
```

## Auth token 발급

Authorization이 필요한 API는 `/users/login`으로 token을 발급합니다.

예시:

```powershell
$loginBody = @{
  account_id = "harness.student.01"
  password = "HarnessPass123!"
  platform_type = "WEB"
  device_token = "harness-student-device-token"
} | ConvertTo-Json

$login = Invoke-RestMethod -Method Post -Uri "http://localhost:18080/users/login" -ContentType "application/json" -Body $loginBody
$token = $login.access_token
```

TEACHER 또는 COMPANY가 필요하면 synthetic 계정 값을 fixture와 맞춥니다.

## 실제 API 요청

GET API 예시:

```powershell
$headers = @{ Authorization = "Bearer $token" }
Invoke-RestMethod -Method Get -Uri "http://localhost:18080/interviews?year=2026&month=3&interview_type=FINAL_INTERVIEW&company_name=자비스회사" -Headers $headers
```

curl 예시:

```powershell
curl -H "Authorization: Bearer <token>" "http://localhost:18080/interviews?year=2026&month=3"
```

## Assertion 확인

request contract의 `qa_expectations.success_assertions`에 맞춰 response를 확인합니다.

확인 예시:

- status code가 success status와 같습니다.
- 필수 field가 존재합니다.
- 배열 개수가 기대값 이상입니다.
- `total_count`와 배열 길이가 일관됩니다.
- authority가 없는 요청은 401 또는 403을 반환합니다.
- 허용되지 않은 authority는 실패해야 합니다.

## report 작성

결과를 아래 파일에 남깁니다.

```text
harness/reports/generated/qa-manual-summary.json
```

예시:

```json
{
  "success": true,
  "request_contract": "harness/requests/generated/interviews-query.json",
  "endpoint": "GET /interviews",
  "authority": "STUDENT",
  "status": 200,
  "assertions": [
    "status matched",
    "required fields exist",
    "negative auth case checked"
  ]
}
```

## 성공 기준

- 실제 HTTP 요청을 수행했습니다.
- success case와 최소 1개 이상의 failure case를 확인했습니다.
- SecurityConfig와 WebAdapter가 contract와 일치합니다.
- 결과 report를 남겼습니다.

## 실패 시 처리

- 401/403이면 token, authority, SecurityConfig를 확인합니다.
- 404이면 WebAdapter path와 base URL을 확인합니다.
- 5xx이면 app log와 구현 코드를 확인합니다.
- response field 누락이면 DTO, mapper, query를 확인합니다.
